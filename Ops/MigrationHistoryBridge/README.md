# جسر سجلّ الهجرات — Migration History Bridge

**التذكرة:** `RECONCILE-PROD-DEVELOP-LINEAGE` · **الحالة:** مُثبَت على نسخ معزولة فقط — **لم يُنفَّذ على أيّ بيئة حيّة.**

## 1. لماذا؟

نَسَب الإنتاج/RC طبّق هجرتين بمعرّفَين زمنيَّين مختلفَين عن معرّفَي `develop` المعتمدَين، مع
**محتوى SQL متطابق حرفيًّا**:

| المعتمد (في التجميعة) | التاريخيّ (مُطبَّق على الإنتاج/RC) | الجدول |
|---|---|---|
| `20260622140138_KpiTemplateAssignmentsPhaseT1` | `20260622144900_KpiTemplateAssignmentsPhaseT1` | `kpi_template_assignments` |
| `20260626124527_AddReportViewGrants` | `20260626135944_AddReportViewGrants` | `report_view_grants` |

بلا الجسر، إقلاع الخدمة على الإنتاج/RC يفشل بـ:

```
Npgsql.PostgresException 42P07: relation "kpi_template_assignments" already exists
```

وتبقى القاعدة **نصف-مهاجَرة** (31 هجرة/61 جدولًا) — أُثبِت عمليًّا على نسخة معزولة.

## 2. ما تفعله الأداة — وما لا تفعله

| ✔ تفعل | ✘ لا تفعل |
|---|---|
| تُدرِج **صفَّين اثنين فقط** في `"__EFMigrationsHistory"` بالمعرّفَين المعتمدَين | أيّ `CREATE`/`ALTER`/`DROP` |
| تنسخ `ProductVersion` من الصفّ التاريخيّ المقابل | أيّ مساس بجدول أعمال أو صفّ بيانات |
| تعمل داخل معاملة واحدة | حذف الصفَّين التاريخيَّين (يبقيان شاهدَي تاريخ) |
| تولّد سكربت تراجع قبل التنفيذ | طباعة أيّ سرّ في الأوامر أو السجلّ |

## 3. الفحوص القبليّة التسعة (كلّها حاجبة)

1. **هويّة البيئة** ضمن قائمة سماح مغلقة `test|rc|production`؛ والإنتاج يحتاج `--allow-production`.
2. **الاتّصال** بالقاعدة وإصدار الخادم.
3. **الالتزام المتوقَّع** (`--expected-commit`) مطابق لـ`HEAD` المنشور.
4. **لا معاملات معلّقة** (`idle in transaction`) على القاعدة.
5. **وجود `__EFMigrationsHistory`** وعدد الهجرات المطبَّقة.
6. **وجود الصفَّين التاريخيَّين** — وإلّا فالبيئة ليست من نَسَب الإنتاج ⟹ رفض.
7. **وجود الجدولَين فعليًّا** — وإلّا فلا مبرّر للجسر ⟹ رفض.
8. **غياب الصفَّين المعتمدَين** — وجودهما معًا ⟹ خروج نظيف `ALREADY-BRIDGED` (idempotent)؛ وجود أحدهما فقط ⟹ رفض (حالة جزئيّة).
9. **بصمة المخطَّط الكاملة** مطابقة سطرًا بسطر للمرجع — وإلّا رفض مع طباعة أوّل 20 فرقًا.

بعد التنفيذ يُعاد التحقّق: عدد صفوف السجلّ = قبل+2، عدد الجداول بلا تغيير، البصمة بلا تغيير.

## 4. الاستعمال

```bash
# 1) تجربة جافّة (الافتراضيّ) — لا تكتب شيئًا
./bridge.sh --db reporting_rc --env rc

# 2) تنفيذ على RC
./bridge.sh --db reporting_rc --env rc --apply

# 3) تنفيذ على الإنتاج (يحتاج العلم الإضافيّ)
./bridge.sh --db reporting_prod --env production --apply --allow-production

# 4) التراجع (يُولَّد تلقائيًّا قبل كلّ تنفيذ)
psql -d <db> -v ON_ERROR_STOP=1 -f /tmp/bridge-rollback-<db>-<ts>.sql
```

الاتّصال عبر متغيّرات libpq القياسيّة (`PGHOST`/`PGUSER`/`PGPASSFILE`…) أو مصادقة peer محلّيّة.
**لا تُمرَّر كلمة سرّ في سطر الأوامر إطلاقًا.**

## 5. الملفّات

| الملفّ | الوصف |
|---|---|
| `bridge.sh` | الأداة |
| `fingerprint.sql` | استعلام بصمة المخطَّط الحتميّة (أعمدة + قيود + فهارس، بلا `__EFMigrationsHistory`) |
| `expected-fingerprint-prod-rc.txt` | البصمة المرجعيّة لحالة الإنتاج/RC قبل الترقية — `e137d40dcd1ad8d088fa6c4ad9a8eebb` (905 أسطر) |

## 6. نتائج الإثبات على النسخ المعزولة

| السيناريو | النتيجة |
|---|---|
| بيئة خارج قائمة السماح (`staging`) | `REFUSED` (exit 3) |
| إنتاج بلا `--allow-production` | `REFUSED` (exit 3) |
| بيئة ليست من نَسَب الإنتاج (نسخة TEST) | `REFUSED` عند الفحص 6 |
| بصمة غير مطابقة (قاعدة نصف-مهاجَرة) | `REFUSED` عند الفحص 9 |
| Dry Run على نسخة RC ونسخة الإنتاج | `DRY-RUN OK` |
| Apply على نسخة RC ونسخة الإنتاج | `APPLIED (2 alias rows)` · الجداول والبصمة بلا تغيير |
| إعادة التشغيل | `ALREADY-BRIDGED (no-op)` |
| الترقية بعد الجسر | 8 هجرات · **بلا `42P07`** · المخطَّط النهائيّ = مخطَّط قاعدة Fresh حرفيًّا |
| تراجع الجسر | عاد السجلّ والبصمة إلى الأصل تمامًا |
