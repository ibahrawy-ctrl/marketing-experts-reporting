## 4. القرارات النهائيّة للـFindings الأربعة

### FINDING-W6-01 — الترقيم
**القرار:** كما في §2 أعلاه. `W6-IG` اسم رسميّ · R2 §17 لا يُعدَّل · التالي `R2-W12`. **مغلق.**

### FINDING-W6-02 — `ProjectKpiSourceType`
**القرار المعتمد:** تبقى القيم الثلاث المطابقة لـR2 السطر 187 وللكود:

```csharp
public enum ProjectKpiSourceType { Manual = 0, TaskDerived = 1, Integration = 2 }
```

**ممنوع في هذه الحزمة:** إضافة `Calculated` · إعادة تسمية `Integration` إلى `IntegrationDerived` ·
تعديل أيّ بيانات مخزَّنة · إنشاء هجرة لهذا الغرض.

**التوسعة المستقبليّة مسموحة تصميميًّا وموثَّقة:** إضافة قيمة إلى التعداد لاحقًا لا تحتاج إعادة تصميم
المؤشّر — الأعمدة الخارجيّة الثلاثة (`ExternalSourceKey` · `ExternalMetricCode` · `LastSyncedAtUtc`)
موجودة أصلًا وقابلة للاستعمال بـ`UPDATE` على صفّ قائم بلا هجرة (D-06). **خارج نطاق CPW-R3 الحاليّة.** **مغلق.**

### FINDING-W6-03 — صحّة المشروع
**القرار المعتمد:** تُنفَّذ **الصحّة المخزَّنة (Persisted Health) قبل الواجهة**.

- `ProjectHealthPolicy` تبقى **المصدر الوحيد** للاحتساب — لا نسخ للمعادلة في خدمة ولا في Controller ولا في React.
- **يُخزَّن فقط:** `HealthStatus` · `HealthPercent` · `HealthComputedAtUtc`.
- **لا يُخزَّن:** `Health.Reasons` — تبقى **مشتقّة لحظيًّا** من الـPolicy (قرار W1-A بند 1، غير منقوض).
- يُضاف مسار إعادة الاحتساب المعتمد في R2 بلا هجرة. **مغلق — يُنفَّذ في المرحلة B.**

### FINDING-W6-04 — مكافحة التعداد (Anti-Enumeration)
**القرار المعتمد:** يُصحَّح `S-01`/`S-02` وفق R2:

| الحالة | العقد المعتمد |
|---|---|
| مستخدم غير مسجَّل | `401` |
| مشروع **غير موجود** | `404` |
| مشروع **موجود خارج نطاق المستخدم** | `404` — **نفس الرمز ونفس الشكل ونفس الرسالة** |
| مستخدم يرى المشروع لكن **لا يملك صلاحيّة العمليّة** | `403` (يبقى متمايزًا — عقد R2 والسياسات العامّة) |

- يجب ألّا يستطيع المستهلك التمييز بين «غير موجود» و«خارج النطاق» بأيّ فارق (رمز · رسالة · شكل · زمن).
- **إخفاء عناصر الواجهة ليس حماية** — الحماية في الخادم حصرًا، وتُختبَر بالوصول المباشر لا عبر الواجهة. **مغلق — يُنفَّذ في المرحلة C.**
