## 5) عقد الأخطاء وربطها بـHTTP

الربط **تلقائيّ باللاحقة** داخل `ApiControllerBase.ToProblem` — واللاحقة جزء من العقد لا زينة:

| اللاحقة | HTTP | أمثلة من W4 |
|---|---|---|
| `auth.unauthenticated` | 401 | كلّ العمليّات قبل المصادقة |
| `auth.forbidden` | 403 | مشروع خارج الرؤية · موظّف يحاول الكتابة |
| `*.not_found` | 404 | `project.not_found` · `project_objective.not_found` · `project_kpi.not_found` |
| `*.conflict` | 409 | `project_objective.has_kpis.conflict` · `project_kpi.objective_mismatch.conflict` · `project_kpi_reading.duplicate_date.conflict` |
| غير ذلك | 400 | أخطاء التحقّق (`*.invalid`) |

هذا يضمن أنّ W5 تستطيع إنشاء الـControllers **بصفر منطق أعمال**: تمرير `Result` فقط.

## 6) الرؤية والتخويل — لا توسيع نطاق، بل تضييق كتابة

`IProject360Authorization` يشتقّ الرؤية **حصرًا** من `IClientProjectAccess` القائم:
لم يُضَف مصدر رؤية جديد، ولا دور جديد، ولا Policy جديدة. الجديد هو **قيود كتابة أضيق**:

| المستوى | الصلاحيّة | من يملكها |
|---|---|---|
| **بنيويّ** | إنشاء/تعديل/حذف الأهداف والمؤشّرات والمخرَجات التعاقديّة والاستراتيجيّة | `Roles.ProjectPlanManagers` = Admin · CEO · GeneralManager · Manager |
| **تشغيليّ** (D-07) | التقدّم والحالة والقراءات اليدويّة | ما سبق **أو** `Project.TeamLeaderId` **أو** `Project.AccountManagerId` |

`LoadVisibleProjectAsync` هو **المدخل الوحيد** لكلّ عمليّة، ويحمّل لقطة `Project360Context`
مرّة واحدة (تشمل الحالة والتواريخ والتقدّم والمسؤولين) فتستهلكها الحرّاس ومحرّك الصحّة معًا
بصفر استعلام إضافيّ. كلا المستويين يُطبَّقان **بعد** التحقّق من الرؤية.

**مضادّ IDOR مُثبَت باختبار**: مشروع موجود لكن خارج النطاق، ومعرّف عشوائيّ لا وجود له —
كلاهما يُرجِع **نفس الرمز `auth.forbidden` بلا أيّ اختلاف**، فلا يُسرَّب وجود المشروع.

## 7) محرّك الصحّة — القرارات المسجَّلة DN-01…DN-08

`ProjectHealthPolicy` دالّات ساكنة نقيّة (بلا `DbContext`، بلا وقت داخليّ — الوقت مُمرَّر)،
وهو ما جعل تغطيتها بـ~44 حالة وحدة ممكنًا دون أيّ قاعدة بيانات.

| المعادلة | الصيغة |
|---|---|
| الإنجاز (الأعلى أفضل) | `(Current / Target) × 100` |
| الإنجاز (الأقلّ أفضل) | `(Target / Current) × 100` |
| الحدّ | مقصور على `0..200` · الانحراف = `achievement − 100` |
| الاتّجاه | نطاق ε = ±2 ⟹ `Flat` |
| التجميع الموزون | `Σ(aᵢ×wᵢ) / Σ(wᵢ)` — كلّ الأوزان صفر ⟹ أوزان متساوية + علم `AllWeightsZero` |
| صحّة الجدول | `expected = (today−Start)/(End−Start)×100` · `gap = Progress − expected` ⟹ 100/75/50/25 عند 0/−10/−25 |
| الصحّة النهائيّة | `0.50×kpi + 0.30×progress + 0.20×schedule` مع **إعادة تطبيع** على المكوّنات المتاحة |
| الحالة | أخضر ≥ 80 · أصفر ≥ 55 · وإلّا أحمر · النتيجة مقصورة `0..100` |

القرارات المثبَّتة: **DN-01** عتبة رمز السبب = الأخضر (80) · **DN-02** تقدّم الهدف **مشتقّ لا مخزَّن** ·
**DN-03** التجميع مسطَّح وفق نصّ R2 حرفيًّا · **DN-04** الأقلّ أفضل مع `Current ≤ 0` ⟹ الحدّ الأقصى ·
**DN-05** تقريب منزلتين `AwayFromZero` · **DN-06** `BaselineValue` إعلاميّ فقط ·
**DN-07** `EndDate ≤ StartDate` ⟹ استبعاد الجدول · **DN-08** مكتمل/مغلق ⟹ 100، معلَّق ⟹ استبعاد.

**`NormalizedWeight` كسر من 0..1 (لا نسبة مئويّة)** مقرَّب لمنزلتين — مثبَّت باختبار (0.75 / 0.25).

## 8) لوحة النظرة العامّة — عدد استعلامات ثابت ومُوثَّق

`GetProjectOverviewAsync` تُنفّذ **10 استعلامات بالضبط**، **مستقلّة تمامًا عن عدد الصفوف**:

1. نواة المشروع + اسم العميل · 2–4. `ProjectObjectiveService.BuildAsync` (أهداف + مؤشّرات + تجميع) ·
5. المؤشّرات النشطة · 6. المخرَجات التعاقديّة النشطة · 7–9. المخاطر/القرارات/الملاحظات ·
10. الاستراتيجيّة + عدّ سماتها.

كلّها `AsNoTracking()`، وكلّ إثراء (أسماء المسؤولين، أسماء أنواع المخرَجات من الكتالوج) يتمّ عبر
**قاموس دفعة واحدة** لا استعلامًا لكلّ صفّ. `ProjectObjectiveService` مسجَّل كنوع ملموس مرّة واحدة
ثمّ يُعاد استعماله عبر الواجهة، كي لا تُنشأ نسختان في الطلب الواحد.

**الصحّة تُحسَب حيًّا ولا تُكتب أبدًا**: أعمدة `HealthStatus` / `HealthPercent` / `HealthComputedAtUtc`
تبقى كما هي بعد القراءة — مُثبَت باختبار يؤكّد بقاء `HealthComputedAtUtc` فارغًا بعد استدعاء اللوحة.

| **Commit** | **NO-GO** | يحتاج تصريحًا صريحًا جديدًا |
| **Push / Merge / PR / Tag** | **NO-GO** | يحتاج تصريحًا صريحًا جديدًا |

## 14) الحالة النهائيّة

كلّ عمل W4 **في شجرة العمل المحلّيّة فقط**، على الفرع `develop`، **بلا Commit**.
لا شيء دُفع، ولا شيء نُشر، ولا قاعدة بيانات حيّة مُسّت.
