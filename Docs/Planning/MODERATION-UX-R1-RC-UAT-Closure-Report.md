## 3) السيناريو الكامل E2E (البند 4)

أُثبت دورة الحياة كاملة على RC بحساب موظف حقيقي وحساب مراجع:

1. **دخول الموظف** → فتح تقرير المودريشن → إنشاء مسودة جديدة (`4c93f528`).
2. **إدخال البيانات** لمشروع مُختار + تعبئة 6 حقول KPI → البطاقات تحدّثت مباشرة (الوصول 48200، التفاعل 6340، المعدّل 13.2، إنجاز المهام 92، المنشورات 18، الاستجابة 96).
3. **حفظ المسودة** → ظهر شريط الحفظ الأخضر «✔ تم حفظ التغييرات · آخر حفظ: 11:18 PM».
4. **الخروج وإعادة الفتح** → البيانات محفوظة بالكامل عبر إعادة تحميل الصفحة الكاملة (persist مؤكَّد).
5. **الإرسال** → حارس التحقق أمسك الحقول الإلزامية الناقصة (400 `submission.repeatable_section_invalid`) → عُبّئت الحقول الثلاثة الإلزامية → إرسال ناجح (200 Submitted).
6. **ظهور للمراجع الصحيح** → التقرير ظهر في قائمة المراجع باسم المُرسِل الصحيح.
7. **الاعتماد** → المراجع اعتمد (200 → **Closed** مباشرةً، اعتماد أحادي المستوى).
8. **Read-Only بعد الاعتماد** → الموظف أعاد الفتح: 0 حقول إدخال، لا أزرار حفظ/إرسال، عرض Accordion + بطاقات KPI في وضع القراءة فقط.

**النتيجة:** ✅ الدورة الكاملة مُثبتة بلا أعطال.

## 5) التوافق الخلفي (البند 6)

منطق `moderationGroups(fields)` يُرجِع `null` عند غياب مفاتيح المودريشن ⇒ يسقط لتخطيط **مسطّح** (flat) للقوالب القديمة، **بلا فقدان أي حقل** (zero field loss).

| القالب | النتيجة |
|---|---|
| تقرير فريق SEO (`ae6f91cf`) | ✅ عرض مسطّح، لا شبكة KPI مودريشن (`grid-cols-6`=0)، لا خطأ، console نظيف |
| تقرير Media Buyer (`2ac253db`، مغلق) | ✅ عرض مسطّح، `grid-cols-6`=0، details=1، لا أخطاء React |
| كاتب المحتوى (`cb6af097`) | ✅ 200/Closed، PRS بـ0 مفاتيح مودريشن (مسار flat) |
| مقالات SEO (`1f7fbc20`) | ✅ 200/Closed، PRS بـ0 مفاتيح مودريشن (مسار flat) |
| تشغيل الأكاديمية (`9cec1eeb`) | ✅ 200/Closed، بلا PRS (مسار flat) |

**النتيجة:** التقارير القديمة (v4/v5/بلا PRS) تفتح بلا أخطاء، بلا فرض schema جديد، بلا فقدان بيانات، وضع Read-Only يعمل. الأخطاء الوحيدة في console = فشل SignalR negotiation المعروف الحميد (غير متعلق).
