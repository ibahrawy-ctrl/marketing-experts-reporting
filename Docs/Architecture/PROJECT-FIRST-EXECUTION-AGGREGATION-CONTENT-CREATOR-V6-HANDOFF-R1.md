# عقد تسليم Content Creator v6 — امتداد على محرّك التجميع الأول-للمشروع (R1-V2)

> **الحالة:** عقد تسليم (Handoff Contract) — Phase 20 من
> `PROJECT-FIRST-EXECUTION-AGGREGATION-CONTRACT-R1-V2`.
> **النطاق:** توثيقي/تعاقدي فقط. **لا كود، لا Migration، لا نشر، لا تعديل قالب** ضمن هذا العقد.
> يحدّد الحدود التي يجب أن يلتزم بها تنفيذ Content Creator v6 المستقبلي كي يندمج مع
> المحرّك القياسي **دون كسر العقد القرائي**.

---

## 1. الغرض

محرّك التجميع الأول-للمشروع (`ProjectFirstExecutionAggregationService`) قياسيّ،
صريح، **قراءة-فقط**، ويعتمد على **خرائط مفاتيح إنتاجية (v5)** مثبَّتة في
`ProjectFirstExecutionSchema`. Content Creator v6 قالبٌ مستقبليّ لكاتب المحتوى
سيحمل تفاصيل تحريرية أغنى (بنية موضوعات/كلمات مفتاحية/حالة نشر لكل قطعة).
هذا العقد يضمن أن **إدخال v6 لا يتطلّب إعادة تصميم المحرّك** وأنّ المحرّك يبقى
مستقرًّا سواء أُطلق v6 أم لا.

## 2. المبدأ الحاكم — لا كسر خلفيّ

- المحرّك يجمع عبر **عنوان القالب** (`ExecutionTemplateTitles`) + **خريطة مفاتيح**
  (`MapFor(title)`). إدخال v6 **يجب** أن يُعامَل بأحد نمطين فقط:
  - **(أ) إعادة استخدام عنوان `ContentTitle` القائم** مع الإبقاء على مفاتيح v5
    الحقيقية (`required_pieces`, `delivered_pieces`, `approved_first_time`,
    `returned_once`, `returned_more`, `late_pieces`, `project_status`) —
    فيُجمَّع v6 تلقائيًّا **بلا أيّ تعديل على المحرّك**.
  - **(ب) عنوان قالب جديد** (مثل «تقرير كاتب المحتوى v6») ⇒ يتطلّب **إضافة سطر
    خريطة واحد** في `ProjectFirstExecutionSchema.MapFor` + إدراج العنوان في
    `ExecutionTemplateTitles`. هذا التغيير **إضافيّ بحت** (لا يمسّ الخرائط القائمة).

- **ممنوع** على v6: تغيير دلالة مفتاح v5 قائم، أو إعادة تعريف `project_status`،
  أو جعل المحرّك يعيد التحقّق من مفاتيح الإجابات وقت القراءة.

## 3. تصنيف الحقول الإلزاميّ لـ v6

على مصمّم v6 تصنيف كل حقل إلى إحدى الفئات الأربع (كما في العقد الأمّ §3):

| الفئة | المعالجة في المحرّك | مثال v6 |
|------|----------------------|---------|
| **مقياس تنفيذ مشترك** | يُجمَّع (SUM، Strategy A) | عدد القطع المطلوبة/المُسلَّمة/المتأخّرة |
| **مقياس خاصّ بالدور** | يُجمَّع ضمن عائلة الدور | المعتمَد أوّل مرّة، المُعاد مرّة/أكثر |
| **حالة مشروع (RAG)** | تُطبَّع عبر `NormalizeStatus` | حالة المشروع الأسبوعية |
| **محتوى تفصيليّ غير قابل للتجميع** | **يُتجاهَل قراءةً** (لا يدخل التجميع) | عناوين الموضوعات، الكلمات المفتاحية، روابط القطع |

**قاعدة حاسمة:** أيّ حقل تحريريّ نصّي/مصفوفة في v6 (موضوعات، كلمات مفتاحية،
ملاحظات) **يُصنَّف محتوى تفصيليًّا** ولا يُضاف إلى أيّ عائلة مقاييس — يبقى مرئيًّا
في التقرير المفصّل الأصلي فقط، خارج نطاق هذا المحرّك.

## 4. خريطة المفاتيح المقترحة لـ v6 (نمط ب — إن لزم عنوان جديد)

إن اختار v6 عنوانًا جديدًا، يجب أن تُبقي الخريطة **نفس دلالات العائلات** كي يبقى
`TotalOutput`/`CompletionRate`/`ApprovalRate` متجانسة عبر النسخ:

```
Planned   → [ required_pieces ]      // أو ما يكافئها من مفتاح v6 صريح
Completed → [ delivered_pieces ]
Approved  → [ approved_first_time ]
Revisions → [ returned_once, returned_more ]
Delayed   → [ late_pieces ]
// عائلة المديرشن تبقى فارغة قصدًا (كاتب المحتوى ليس مديرشن) لمنع ازدواج
// TotalOutput = Completed + Responses.
MessagesIn/Responses/IssueComments/Escalations → فارغة
StatusKey → project_status
```

## 5. حدود العقد الأمّ التي لا يتجاوزها v6

- المحرّك يبقى **backend-only، read-only**: لا كيانات، لا جداول، لا Migration،
  لا Frontend، لا Jobs/Email/Scheduler من طرف v6.
- **الأمان والنطاق** يبقيان محكومَين بـ `IScopeResolver` + `IClientProjectAccess`
  (لا يُوسّعهما v6).
- **الاستبعاد:** المسودّات (`Status == Draft`) تبقى مُستبعَدة؛ v6 لا يغيّر أهليّة
  التسليم.
- **التكرار (Strategy A = SUM/تراكم)** يبقى سياسة موحّدة عبر كل النسخ.

## 6. شروط توقّف تُلزم v6 بالرجوع لقرار تعاقديّ

على منفّذ v6 التوقّف وطلب قرار إن استلزم أيّ ممّا يلي:
- تغيير دلالة مفتاح v5 قائم أو إزالته.
- الحاجة إلى Migration/كيان/جدول جديد لأجل التجميع.
- جعل المحرّك stateful أو كتابيًّا.
- توسيع نموذج الصلاحيات/النطاق.
- إدخال حقل يتعذّر تصنيفه ضمن الفئات الأربع.

## 7. اختبار القبول لأيّ إدخال v6 مستقبليّ

- إضافة اختبار وحدة في `ProjectFirstExecutionSchemaTests` يؤكّد
  `MapFor(v6Title)` يُرجِع الخريطة المتوقّعة وأنّ عائلة المديرشن فارغة.
- إضافة اختبار تكامل معزول (قاعدة `reporting_pfe_iso`) يبذر تسليم v6 ويؤكّد
  المقاييس المجمّعة + الحالة المطبَّعة + الأهليّة (استبعاد المسودّة).
- عدم انحدار: النسخ القائمة (v5) يجب أن تبقى خضراء دون تعديل.

## 8. خلاصة التفويض

Content Creator v6 **مُصرَّح له باستئناف التنفيذ** فوق هذا المحرّك القياسي، شريطة
الالتزام الحرفيّ بالبنود 2–6. المسار المُوصى به = **نمط (أ)** (إعادة استخدام
`ContentTitle` + مفاتيح v5) لأنّه يجمّع v6 **بلا لمس المحرّك إطلاقًا**؛ ونمط (ب)
مسموح كإضافة سطر خريطة واحدة عند الحاجة لعنوان مستقلّ.
